# WhaleSwitch 1.4 源码审查

审查涵盖桌面入口、前端状态、三种 CLI 的适配器、文件访问、加密快照、网络诊断、测试和发布脚本。以下结论以 1.4.0 仓库中的实现为准。

## 代码分工

| 代码 | 职责与边界 |
| --- | --- |
| `src-tauri/src/main.rs`、`lib.rs`、`desktop.rs` | Tauri 装配共享的 Rust 引擎，注册 IPC 并将错误转换为枚举。项目目录和导入导出路径由系统对话框选择。会进行文件 I/O 或密钥操作的新增命令通过后台线程运行。 |
| `src-tauri/src/adapters.rs`、`jsonc.rs` | 路径解析和字段允许列表与三种 CLI 绑定。TOML 使用 `toml_edit`，JSON 与 JSONC 使用局部替换。解析拒绝重复键和过深的对象。已有未知键及其相邻注释可在支持字段的修改期间保留。 |
| `src-tauri/src/engine.rs` | 将预览、保存和恢复绑定到工具、路径及内容修订。写入通过跨实例锁、快照验证、同目录暂存和原子替换。替换后校验失败时，只有当前字节仍是该次写入的内容才尝试恢复。 |
| `src-tauri/src/storage.rs`、`profiles.rs` | SQLite 保存元数据、加密快照及档案字段。快照用 XChaCha20-Poly1305 加密，解密需要操作系统密钥库中的密钥和原快照对应的工具与路径。档案 JSON 保留显式清除值，应用时重新检查字段。 |
| `src-tauri/src/sources.rs`、`skills.rs` | 用户主动选择项目目录后，检查固定配置和技能候选路径。项目配置报告只返回支持字段名，技能报告只返回路径、候选工具、同名提示和指纹等元数据。文件大小、目录数量和链接类型均有边界。 |
| `src-tauri/src/probe.rs` | 手动请求 Models 端点，返回分类状态、耗时和模型数量。连接密钥绑定工具、协议和具体请求 URL。应用禁用自动重定向和系统代理继承，回环地址可使用受限的无密钥模式。 |
| `src/api.ts`、`domain.ts`、`demo.ts` | TypeScript IPC 数据结构、允许字段和草稿补丁。浏览器使用内存夹具，原生写入和安全存储在桌面端执行。 |
| `src/app.tsx`、`config-session.ts` | 配置会话跟踪已接受的基线、最新文件状态和草稿。发现同一路径的外部改动后可选择冲突字段，路径切换暂停对旧草稿的合并。旧预览由目标和修订守卫。 |
| `src/components/`、`src/i18n.ts`、`src/styles.css` | 配置来源、三栏差异、档案、技能和连接测试的中英文界面。React 渲染外部路径和字段，差异确认用原生对话框元素。主题和语言是本地偏好。 |
| `src/main.tsx`、`vite.config.ts`、`tsconfig.json`、`index.html`、`components.json`、`src/lib/utils.ts` | React 启动、Vite 资产入口、TypeScript 严格配置和 UI 组件约定。桌面边界另由 Tauri CSP 与能力文件限制。 |
| `src-tauri/build.rs`、`Cargo.toml`、`tauri.conf.json`、`capabilities/default.json` | Rust 核心可在关闭桌面特性时跑测试。生产包载入本地前端，能力配置提供窗口和事件等核心接口。前端通过专用命令执行文件、网络和对话框操作。 |
| `tests/`、`src-tauri/tests/` 与各模块单元测试 | 前端覆盖模拟工作流、修订合并和档案。Rust 在临时目录与替代密钥库中验证配置保留、陈旧修订拒绝、备份、回滚和链接保护。 |
| `scripts/stage-installers.mjs`、`.github/workflows/checks.yml` | 四平台分别打包后生成统一命名的安装包和 SHA-256。发布任务检查三个版本号、四组资产的名称与内容哈希。发布分支的目标提交须已在 `main` 内。 |

## 写入路径

1. 前端依据最新配置创建工具、绝对路径和修订号组成的目标，再提交允许字段的补丁预览。
2. 确认时，引擎重新绑定目标并读取当前内容。已有文件先写入加密快照，验证快照可解密，然后暂存并再次检查文件状态。
3. 同目录原子替换后校验文件字节。恢复操作使用同一写入保护，完整恢复会写回已有快照的原始字节。

## 发布与维护发现

| 优先级 | 发现 | 后续验收条件 |
| --- | --- | --- |
| P0 | 1.4 的快照恢复会写回完整文件。 | 字段级恢复应复用同一写入引擎，保留当前文件中的未选字段及未知键。完整快照仍可恢复语法损坏的文件。 |
| P0 | Node 和 Cargo 的锁文件尚未随仓库提交。 | 按版本锁定依赖，在 CI 中使用 `npm ci` 与 Cargo 锁定模式，并核对各平台上生成的包。 |
| P0 | CI 的快照和密钥库测试使用替代实现。 | 在原生系统上以临时配置完成安装、启动、目录授权、真实密钥库读写与恢复复测，再检查签名与发布状态。 |
| P1 | 项目配置和技能页展示候选项，实际加载受版本、工作目录和信任设置影响。 | 能按文档与版本展开来源路径，并清楚标明状态所用的证据。 |
| P1 | 连接诊断把部分传输失败聚合为 `network_error`，快照列表也缺少按时间查找与固定入口。 | 为可靠可区分的传输问题提供细化状态。添加不含字段值的操作记录和快照查找。 |

应用锁协调 WhaleSwitch 实例之间的写入。第三方 CLI 仍能在最终读回检查与系统替换之间改写文件。恢复和写入的更详细边界见 [架构与安全](ARCHITECTURE.md)。

## 本次发布改动与验证

- 中文主 README 和英语 README 共用新横幅，并按平台标明安装包文件名、校验方式、配置范围和数据边界。
- CI 将 TypeScript 类型检查提前到打包前，发布校验要求四个平台各有一个安装包和一个匹配的 SHA-256 文件。
- 安装包校验测试使用临时文件覆盖资产齐全、缺少校验文件和字节被改动三种情况。运行器构建证明可打包，真实桌面安装与系统密钥库交互按发布说明记录。
