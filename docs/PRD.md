# WhaleSwitch 0.1 产品需求

## 产品目标

给同时使用 Codex CLI、Claude Code 和 OpenCode 的开发者提供一个本地工作台，集中查看和编辑用户级配置。保存前可核对差异，保存后可恢复到之前的文件版本。

## 首版流程

1. 打开应用后，通过 PATH 检测三个 CLI，独立显示安装状态和配置文件状态。已存在的配置可直接管理。
2. 选择工具，查看支持字段、实际文件路径、配置格式和文件版本。在界面上修改字段，通过差异预览核对增删改，再确认写入。
3. 随时建立当前文件快照。历史页显示各次快照，可比较当前文件与历史字段，并恢复同一路径的快照。
4. 将支持字段导出为 WhaleSwitch JSON，或导入同一工具的档案，在保存前预览差异。
5. 输入明确签发的 API 密钥进行模型列表连接测试。使用系统密钥库保存与目标 URL 绑定的密钥。测试由用户手动触发。

## 范围

仅管理三个工具的用户级配置。项目配置、组织策略、实际会话级设置、SSO、订阅账户和 CLI 登录交由原工具处理。只显示经官方资料核实并纳入允许列表的字段，其余内容在编辑时保留。导出仅包含可编辑字段，不包含原始文件或快照。连接测试验证模型列表端点的 HTTP 鉴权及响应形状，推理、模型可用性和 CLI 实际会话仍由原工具验证。

## MVP 验收

| 编号 | 可验证结果 |
| --- | --- |
| A1 | 三种 CLI 的安装与配置状态能独立显示，缺失、解析错误及存在多个 OpenCode 全局配置时有明确反馈。 |
| A2 | 三种格式都能编辑已核实字段。未知字段及 TOML、JSONC 注释经编辑保留。支持字段的删除与新增可在预览中辨识。 |
| A3 | 覆盖现有配置前，原始字节先加密写入 SQLite、提交并验证。外部修改使旧预览失效。 |
| A4 | 同目录临时文件同步后替换。注入的替换前失败会保留原文件。替换后可验证的失败会恢复原字节，无法确认时保留备份并提示。 |
| A5 | 手动快照可以比较和恢复。恢复现有配置之前先记录其当前版本。快照只可恢复到原始路径。 |
| A6 | 导入和导出适用同一字段白名单。未知字段、越界体积、格式错误、跨工具档案被拒绝。 |
| A7 | 保存的 API 密钥不会进入 CLI 配置、SQLite、导出或日志。探测走明确目标且禁止重定向。 |
| A8 | 浅色与深色、中英切换、键盘导航、无配置和错误状态可用。Windows、macOS、Linux 均配置 CI 构建。 |
